# 内置浏览器、发送确认与恢复

## 能力预检

1. 从当前宿主的工具 / 技能目录识别内置浏览器能力，读取实际提供者的指南并遵守初始化规则。如果当前环境确实提供 `browser:control-in-app-browser`，加载它；如果通过其他工具提供内置浏览器，使用其文档化入口，不猜 API。
2. 确认能访问页面、读取当前选择器的可访问状态并发送消息；上传 / 下载属于可选能力，按任务需要确认。能力存在不代表已经登录或模型可用。
3. 缺失内置浏览器或操作指南：报告缺项与宿主启用方式（只能使用已知信息），停止外部步骤，继续独立且已授权的本地工作。用户指定内置浏览器时，不改用 Chrome、网页搜索、API 或外部浏览器。
4. 登录、账号选择、验证码、密码、Passkey、两步验证由用户操作。暂停认证相关步骤，等待明确就绪后恢复原对话并重验模型；不读取认证材料。

为独立任务建立空白对话，同一任务追问保持原对话。任何任务消息、源码、附件或背景发送前，执行 SKILL 入口的模型门禁。已选中目标时直接核实；只有尚在初始选模阶段且未失败时可以选中配置目标。已判定门禁失败后不得通过切换或新建对话重试。

## 最小任务记录

长任务使用仓库既有任务记录或独立临时目录保存 [会话记录示例](../assets/session.example.json) 的字段。小任务可以保存在当前任务上下文，不强制创建仓库文件。

至少记录 `taskId`、`turnId`、对话链接、解析后的模型、最近门禁标签 / 控件来源 / 检查时点、本轮请求指纹、发送前最后一条助理回复的可见标识、发送确认、已收到回复的标识和状态。没有稳定消息 ID 时使用本轮任务标识、可见消息次序和确认时点的组合；不得虚构平台消息 ID。

请求正文带简短的 `taskId/turnId`，便于恢复对应关系。记录不包含 Cookie、认证 token 或整段聊天正文；状态描述必须带实际观察时间，旧记录不是当前生成状态的证明。

## 状态与允许的下一步

| 状态 | 必要证据 | 允许的下一步 |
| --- | --- | --- |
| unstarted | 尚未完成本轮准备；示例记录默认处于此状态 | 核对范围、配置和能力，尚不发送 |
| prepared | 配置、权限、上下文和本次 UI 门禁已检查；尚未发送 | 发送本轮请求一次 |
| submission_unknown | 已尝试发送，但工具超时或未看到确认 | 恢复原链接，查找本轮用户消息；不得重发 |
| submitted | 当前对话中出现本轮用户消息，附件也明确已就绪 | 等待或检查本轮生成状态 |
| generating | 当前对话仍有正在思考 / 生成或停止控件的现场证据 | 继续等待，保留页面 |
| interrupted | 确认连接断开、页面明确报错，或生成异常消失且没有完整回复 | 原链接恢复，重新验门禁并核对消息；不取消后台推理 |
| completed | 本轮请求后的助理回复已结束，页面无生成状态、无错误，交付满足请求格式 | 读取该回复和附件一次，进入接入检查 |
| received | 已收取对应回复，记录来源和文件身份 | 审查、验证，或按本轮缺陷发起新的 turnId |
| gate_failed | 当前 UI 证据不足、冲突、回退或不可用 | 终止外部调用，不自动重选、重发或新建对话 |

发送结果未知时，只有现场证据能确定该消息未提交，且原操作已终止、没有仍在执行的工具句柄，才可在同一 turnId 下重新尝试。若无法确定，就保留未知状态并说明阻塞；不能把“没看见回复”当成“没发送”。

恢复时先核对链接、任务标识、最后确认的用户消息与回复，再做决定。门禁失败优先于发送 / 生成状态；同一已失败调用不能因刷新后标签恢复而重新开放。已确认读过的回复不得再次应用。

## 等待与完成判据

- 30 分钟到 1 小时的推理不等于卡死，不设置仅基于经过时间的强制超时。不点击停止或立即回答、不催促、不刷新正常生成的页面、不重复发任务。
- 优先使用不返回正文的等待 / 完成事件，单次等待不超过 60 秒。无异常且用户未要求实时监控时，最小状态核对至多每 5 分钟一次；不反复读取 DOM、截图、流式半成品或消息历史。连接状态未知时应重新建立观察，而不是把旧“生成中”一直当成当前事实。
- 用户询问进度时说明最近确认的状态及时间；等待中继续独立本地工作，但不能跳过用户要求的外部评审提前定稿。
- “停止控件消失”本身不证明完成。回复必须位于本轮已确认用户消息之后，且不是错误、阶段性说明或缺少必要文件的半成品。附件必须实际可取得并核对对应关系；失效附件只能在原对话要求重新提供，不推断交付成功。
- 完成后只读该条完整回复、相关附件和必要元数据；只有可访问元素无法判断时才截图。明确用户停止要求优先，保留恢复信息。

## 分批文本与上传

自动上传只在页面明确显示附件就绪后算成功；未确认的附件不能作为目标模型已有上下文。上传不可用时，按 `taskId / part n/N` 分批提供必要文本，最后一批附完整任务和“资料已齐，可开始”的标记。中途不得把目标模型抢先生成的回答当最终交付；先补齐资料，再用新 turnId 明确要求基于全部资料回答。

分批发送也需要每次核对门禁并记录确认；发送未知时先查原对话。只有附件确实无法由文本替代时，请用户手动上传一次。
